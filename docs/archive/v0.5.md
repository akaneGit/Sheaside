# v0.5 複数シート選択

## 操作

| 操作 | Sheasideの選択 | Excelのアクティブシート |
| --- | --- | --- |
| 通常クリック | 対象1件にする | 対象をアクティブ化（非表示なら案内のみ） |
| Ctrl＋クリック | 対象を追加／解除 | 変更しない |
| Shift＋クリック | 基準行からの範囲にする | 変更しない |
| Ctrl＋Shift＋クリック | 既存選択に範囲を追加 | 変更しない |
| Ctrl＋A | 一覧にフォーカスがある場合だけ全選択 | 変更しない |
| Esc | アクティブシート1件に戻す | 変更しない |
| 選択済み行の右クリック | 選択集合を維持 | 変更しない |
| 未選択行の右クリック | 対象1件にする | 変更しない |
| Enter | 1件選択時だけ切り替え | 対象をアクティブ化 |

選択背景と「N件選択中」を表示し、実際のアクティブシートは「●」で区別します。タブ色・Hidden／VeryHidden・グラフ表示は維持します。Excelの複数シート選択（グループ化）のAPIは呼びません。

複数選択時は追加ボタン・管理メニュー・ダブルクリックによる名前変更・ドラッグ並び替えを無効化します。操作する場合は通常クリック、未選択行の右クリック、またはEscで1件にしてください。複数選択中から通常クリックを始めた場合、そのマウス操作では並び替えを開始せず、1件にした後の次のドラッグから使用できます。一括操作は今回実装しません。

## 設計と互換性

- 既存ListBoxを`MultiExtended`に変更しています。v0.5.1以降はマウスの修飾選択・ドラッグを明示的に処理し、標準マウス範囲選択との競合を防ぎます。キーボードの拡張選択は維持します。詳細は[v0.5.1の修正記録](v0.5.1.md)を参照してください。
- `SheetSelectionState`をパネルごとに持ち、選択ID集合・範囲の基準ID・アクティブIDを分離します。表示中のブック名や行番号を選択の識別子にしません。
- `SelectedSheetIds`は表示順のID配列のスナップショットです。将来の一括操作から共通利用できます。一括操作には、開始時のブック／ウィンドウと全対象の再検証が別途必要です。
- v0.4.1までのCodeName／名前による識別から、サービス内のブック別COMオブジェクト→GUID登録へ変更しました。CodeNameが空でも名前変更・移動でIDは変わらず、同名の別ブックや削除後の再作成は別IDになります。
- COM参照はUIへ渡しません。登録は開いているブックの寿命に合わせ、一覧取得時に削除済みシートを、ウィンドウ取得時に閉じたブックを除去し、終了時にも全登録をクリアします。共有RCWを強制解放しません。
- 一覧更新時は存在するIDだけを残し、選択・範囲基準・スクロール位置を復元します。全選択対象が削除された場合はアクティブシートへ戻します。Ctrl操作で意図的に0件にした場合は空の集合を維持します。
- 通常の単一選択では従来のExcelアクティブ同期を維持します。Ctrl／Shift／全選択で作った選択集合は、Excel側のアクティブ変更や操作後の推奨選択IDによって破棄しません。通常クリック／Escで従来の同期へ戻ります。
- 選択中・ドラッグ中には一覧再構築を保留します。変更のない更新で全件描画や選択のクリアはしません。

## Microsoft 365実機確認

Visual Studio 2026で`Sheaside.slnx`を開き、Debug / Any CPUでF5起動します。ワークシート・グラフシート・Hidden・VeryHiddenを混在させ、スクロールが必要な枚数のテスト用ブックを用意してください。

1. 通常クリックで1件選択し、表示シートに切り替わること、非表示シートは再表示されず案内が出ることを確認します。
2. Ctrlクリックで離れた行を追加／解除します。最後の1件を解除して0件になっても、3秒後の更新で勝手に選び直されないことを確認します。
3. 通常クリックで基準行を決め、Shiftクリックで前方／後方の範囲を選びます。Ctrl＋Shiftで離れた範囲を追加し、元の選択が残ることを確認します。
4. 修飾クリックの間はExcelのアクティブシートが変わらず、Excelのタブがグループ化されないことを確認します。「●」と選択背景・件数が独立していることを確認します。
5. 一覧にフォーカスを置いてCtrl＋AとEscを試します。全選択／アクティブ1件へ切り替わり、スクロール位置が維持されることを確認します。セルにフォーカスを戻すとExcel本来のCtrl＋Aが働くことも確認します。
6. 選択済み行の右クリックで集合を維持し、管理メニューが無効になることを確認します。未選択行の右クリックではその1件だけが対象になり、通常の操作が使えることを確認します。
7. 複数選択中にドラッグしても順序が変わらないこと、1件にした後の次のドラッグでは従来どおり並び替えられることを確認します。ダブルクリックの名前変更も1件選択時に確認します。
8. 複数選択を保ったままExcel側でシートの名前・色・表示状態・タブ順を変更します。約3秒後またはウィンドウ切り替え後も同じシートが選択され、Shiftの基準も同じシートを指すことを確認します。
9. Excel側で選択集合の一部を削除して残りが維持されること、全対象を削除した場合はアクティブシートに戻ることを確認します。同名で再作成しても以前の選択を引き継がないことを確認します。
10. Excelのタブを切り替えてもSheasideの複数選択が残り、「●」だけが移ることを確認します。Escで新しいアクティブシートだけを選択します。
11. 同名シートを持つ2ブック、および同一ブックの2ウィンドウで別々の集合を選びます。切り替え・ブック名変更・閉じて新規ブック作成をしても選択が混ざらないことを確認します。
12. v0.4.1のワークシート／グラフの全管理操作、リボン表示切り替え、構成保護・読み取り専用での拒否、ドラッグ中止も再確認します。

## 既知の制約と検証環境

Debug / Releaseは警告・エラー0でビルド成功。`tools/Test-Sheaside.ps1`は260チェック、`tools/Test-Sheaside.ps1 -Excel`は既存回帰を含む372チェックが成功しました。UIテストはスレッド内のキー状態とネイティブマウスメッセージで修飾選択を検証し、隠れたコントロールでは自動発生しないMouseClick通知は別途送って操作経路を検証しています。

- 選択集合と内部IDはExcel起動中だけ有効です。閉じて開き直したブックやExcel再起動への永続化は行いません。
- 一括操作・複数シートのドラッグ移動は未実装です。複数選択時の管理操作は無効化しています。
- Escでアクティブシートを選んでもスクロール位置を優先するため、対象行が画面外に残ることがあります。
- 自動Excel連携テストの環境はExcel 2013 / 15.0です。v0.4.1まではユーザー側でMicrosoft 365実機確認済みですが、v0.5は上記手順での確認が必要です。
- Excel 2013の非表示自動化では、既存の複製直後の削除や複数ウィンドウ後のグラフ削除がCOMエラーになるケースがあります。アドインは例外を案内して実際の一覧へ戻します。今回の検証中にもグラフ削除で発生したため、複数ウィンドウの削除テストでは各ウィンドウを非対象シートへ切り替えてから削除を検証しています。単一ウィンドウでのアクティブグラフの複製・削除テストは継続しています。
- Windowsシステム色を用いる描画、条件付き約3秒同期、グラフシート新規作成の対象外など、従来の制約は継続します。

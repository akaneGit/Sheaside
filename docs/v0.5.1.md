# v0.5.1 複数選択のマウス操作修正

## 原因

v0.5は左ボタン押下をネイティブListBoxへ渡していました。Ctrl＋Shiftの範囲追加をアプリ側で保証せず、ネイティブの選択動作に依存していました。また、複数選択時の`blockDragGesture`はSheasideのDoDragDropだけを抑止し、ListBox自体のマウス移動による範囲選択を止めていませんでした。

既存テストは一部の修飾クリックと管理イベントを確認していましたが、押下から移動・解放までのネイティブメッセージによる競合の検証が不足していました。

## 修正内容

- 左ボタンの押下・移動・解放をSheasideで処理し、ListBoxの標準マウス範囲選択へ渡しません。キーボードの拡張選択は維持します。
- 押下時の選択集合・アンカー・修飾キー・クリック行・ドラッグ可否を記録します。修飾キーは押下メッセージのフラグから取得します。
- Ctrl＋Shiftを最優先で判定し、押下時の集合と範囲の和集合にします。Shift単独は範囲で置き換えます。
- 通常クリック・Ctrlクリックは対象行を次のアンカーにします。Shift／Ctrl＋Shiftはアンカーを更新しません。Ctrlでアンカー行の選択を解除しても、その行が存在する限り次の範囲の基準として使います。
- 複数選択から未選択行を押すと1件に変更し、そのジェスチャーでは並び替えも移動中の範囲選択もしません。選択済み行を押すと集合を保持し、移動せず同じ行で離したときだけ1件にします。
- 修飾キー付きの押下はその時点の選択だけを適用し、その後キーを離しても同じジェスチャー中は並び替えません。
- 単一選択からの通常ドラッグは既存の閾値・並び替えを維持します。ダブルクリック・右クリック・選択更新・Excel操作のサービス層は従来の経路を使います。
- キャプチャ喪失・キャンセル時はクリックを実行せず追跡を終了します。ドラッグ終了時には実際の順序を再取得できるよう選択中フラグを解除します。

## 変更ファイル

- `Sheaside/Controls/ReorderableSheetListBox.cs`：明示的なマウス選択・キャプチャ・クリック／ドラッグの制御。
- `Sheaside/Controls/SheetListControl.cs`：通常クリック完了時に通常の単一選択同期へ戻す処理。
- `tests/SelectionTests.cs`：連続範囲追加、Shiftとの違い、アンカー、押下状態別ドラッグ、キャンセル、ダブルクリックの検証。クリック通知を手動補完せず、押下／解放メッセージから検証。
- `tests/SmokeTests.cs`：新しい回帰テストの呼び出し。
- `README.md`、`docs/v0.5.md`、`docs/v0.5.1.md`：現行の仕様・検証記録。

## Microsoft 365実機確認

自動検証は管理コード277チェック、Excel連携を含む389チェックが成功しました。Debug / Releaseビルドは警告・エラー0です。v0.5以前の回帰に加え、押下・移動・解放・キャンセル・ダブルクリックのネイティブメッセージを使って検証しています。

Visual Studio 2026でDebug / Any CPUをビルドし、F5でExcelを起動します。A～J相当の10枚のシートを用意し、グラフ・Hidden・VeryHiddenも混在させます。

1. Aをクリック、IをCtrlクリック、GをCtrl＋Shiftクリックします。AとG～Iが選択され、Aが消えないことを確認します。
2. 続けてJをCtrl＋Shiftクリックし、AとG～Jが残ることを確認します。次にHをShiftクリックし、H～Iだけになることを確認します。さらにFをShiftクリックしてF～Iとなり、アンカーIが維持されることを確認します。
3. IをCtrlクリックして解除後、JをCtrl＋Shiftクリックし、Iが範囲に戻ることを確認します。通常クリック／Ctrlクリックで新しい基準行を指定できることも確認します。
4. 複数選択中の未選択行を押したまま、ほかの行や一覧外まで動かします。押した行だけが選ばれ、移動先まで範囲選択されず、Excelのシート順も変わらないことを確認します。
5. 複数選択中の選択済み行から同じ操作を行い、元の集合が維持されることを確認します。元の行まで戻って離しても集合を維持します。移動しない通常クリックなら1件になり、そのシートへ切り替わります。
6. Ctrl・Shift・Ctrl＋Shiftを押してドラッグし、押下時の選択だけが反映され、並び替えも移動中の範囲拡大もしないことを確認します。ドラッグ途中で修飾キーを離しても並び替えを開始しません。
7. 1件選択にした後の通常ドラッグで、前方・後方・先頭・末尾に並び替えられること、移動後に一覧が更新されることを確認します。Escやブック切り替えによる中止も確認します。
8. Ctrl＋A／Esc、選択済み／未選択行の右クリック、単一行のダブルクリック、名前変更・追加・削除・複製・表示状態・色・リボンを再確認します。
9. Excel側のシート切り替え・名前変更・並び替え後の選択とアンカー維持、2ブック・同一ブックの2ウィンドウの独立も確認します。

自動連携テスト環境はExcel 2013 / 15.0です。Microsoft 365での修正後のマウス操作は上記手順での確認が必要です。内部ID・選択の寿命、一括操作未対応などv0.5の制約は継続します。
